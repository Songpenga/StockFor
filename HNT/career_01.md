## 1. 현재 이력서 항목 원문

### 프로젝트 A — 엑셀/업로드 개선

- 하드코딩된 엑셀 컬럼 파싱 인덱스 구조를 동적 매핑 방식으로 리팩터링하여 컬럼 추가/삭제/순서 변경 등 비즈니스 요구사항 변화에 유연하게 대응 가능하도록 구조 개선
- 기존 업로드 오류 발생 시 일부 데이터만 Insert 되고 누락 건이 통보되지 않던 문제를 오류 발생 시 전체 Rollback 처리 및 명확한 에러 메시지를 반환하도록 트랜잭션 관리 구조 개선 제안 및 적용

### 프로젝트 B — 기업 인증서 기반 회원/신청 시스템 (개발 진행 중)

- 기업 공인인증서 기반 마스터 계정 회원가입 및 하위 사용자 권한 관리 기능 개발
- 회원가입 프로세스 다변화에 대응하기 위한 단일 상태 플래그 기반의 상태 머신 구조 설계 및 제안 — 잦은 기획 변경(3차례) 속에서 기존 2개 이진 플래그(use_yn + 상태) 대비 조건 분기 복잡도를 대폭 감소시켜 코드 가독성 및 유지보수성 향상 (PM 채택 및 적용)
- 기업별 연월 단위 구매·생산·판매·재고 신청 처리를 위한 상위 모델 연동 및 기자재 분류별 다중 탭 입력 구조 구현
- 다중 사용자 동시 편집 시 데이터 무결성 위험(덮어쓰기, 제출 후 수정 충돌) 식별 및 동시성 제어 로직 제안

### 프로젝트 C — 성능 개선 및 버그 수정

- 민원 접수 목록 조회 성능 저하 이슈 대응 (조회 속도 약 1.7초 개선) — DB 실행계획 분석을 통해 Full Table Scan 구간을 식별하고, 복합 인덱스 구성 및 WHERE 절 조건 최적화를 통해 쿼리 성능 개선
- 특정 사용자 게시글 중복 노출 버그 수정 (서브쿼리 JOIN 조건 누락 확인 및 보완)
- 공공기관·민간사업자·진단기관 3개 사용자 테이블의 UNION ALL 통합 조회 구현 및 초기 대용량 로딩 속도 방지를 위한 페이징 처리 최적화
- 게시판 카테고리별 권한 관리 기능 개발 (사용자 유형별 열람 권한 분리)
- 운영/개발 서버 DB 스키마 불일치 문제를 해결하기 위해 패키지·프로시저 범위 기준의 ERD 정합성 정리 및 누락 컬럼/코멘트 보완

### 프로젝트 D — 사업신청서 시스템

- 신청 기간 기반 로그인·회원가입 접근 제어 로직 설계 및 구현 (기간 외 접근 차단)
- 주관기관 탭 완성 여부에 따른 단계별 탭 잠금/해제 UX 구현
- 참여기관 등록·수정·삭제 시 주관기관·참여기관·공공기관 간 사업비 비중 자동 재계산 — loop UPDATE 쿼리로 전 기관 일괄 반영
- 기관 유형별 첨부파일 목록을 동적 쿼리로 분기 제공
- 동일 소속 참여기관의 행을 JS filter를 활용한 셀 병합으로 처리, 가독성 개선
- 신청서 상태(작성 → 제출 → 보완 → 검토) 전 단계 입력 요소 상태 제어 구현

### 프로젝트 E — 양도양수/공장변경 신청 시스템 (hieff)

> 코드 검증 완료 (2026-06-15) — JSP 파일 및 Oracle Package Body SQL 분석

- 사용자 회원가입·로그인·정보변경·비밀번호 변경·아이디 찾기 프로세스 개발
- 양도양수 신청 프로세스 구현 (Radio 버튼 선택값에 따른 9가지 경우의 수를 분기하여 첨부파일 목록을 동적으로 구성)
- 고시 기준 및 데이터 시점별 변동성을 반영한 다중 조건 복잡 쿼리 설계 및 데이터 정합성 검증, 조건별 첨부파일 동적 제공

## 4. 코드 검증 결과 (프로젝트 E — hieff 양도양수)

코드 파일 분석을 통해 이력서 기재 내용이 실제 구현과 일치하는지 검증함.

### 검증된 항목

**양도양수 신청 프로세스 (6탭 + 복수 팝업)**
```
[목록] → [신청서 작성] → [공장 등록] → [모델 확인] → [첨부서류] → [자가점검/제출]
상태 흐름: 300(작성) → 320(검토중) → 305(보완) → 341(승인)
```

**9가지 경우의 수 분기 — 검증됨**

Radio 버튼 4개 그룹의 조합으로 분기:
- `P_TRANS_SCT` (양도양수구분)
- `P_IDEN_RPSTAV_YN` (동일대표자여부)
- `P_FACT_YN` (공장소재지 변경여부: 0/1)
- `P_FACT_CRTIF_SCT` (공장심사구분: 1/2/3)

첨부파일 동적 구성 쿼리 (`AST_A0_05_04_010_S`):
```sql
'Y' = (CASE WHEN INSTR(B.DTL_SCT, C.TRANS_SCT) > 0 THEN 'Y'
            WHEN A.FACT_CRTIF_SCT = '3' AND INSTR(LTRIM(B.DTL_SCT,'0'), A.FACT_CRTIF_SCT) = 2 THEN 'Y'
            WHEN INSTR(B.DTL_SCT, C.TRANS_SCT,-1) = 1 AND C.TRANS_SCT IN ('03') THEN 'Y'
            WHEN B.DTL_SCT = 'A' THEN 'Y'
            ELSE 'N'
       END)
```

자가점검 시 분기 (`SP_A0_05_05_010_M`):
- FACT_CHG_YN(0/1) × FACT_CRTIF_SCT(1/2/3) 조합으로 공장 등록 경우의 수 처리
- 양도자/양수자 동시 진행 중복 체크
- 필수 첨부파일 누락 체크

**상태별 disabled/readonly 컨트롤 — 검증됨**
```jsp
<c:if test="${fn:escapeXml(not empty resultMap.MOVN_STAT_CODE)}">disabled</c:if>
```
- `MOVN_STAT_CODE` 존재 여부로 전체 Radio/Input 비활성화
- 300(작성중): 편집 가능, 삭제 버튼 표시
- 305(보완요청): 별도 재신청 버튼, Radio disabled
- 320 이상: 전체 readonly

## 5. 이력서에서 부족한 부분

### 치명적 Gap (서류 탈락 가능성)

**① AWS 경험 없음**
- JD 필수 요건임
- 이번 주 키움증권 프로젝트 EC2 배포 완료 후 즉시 추가
- 추가 예정 문구: `"AWS EC2/RDS 환경 개인 프로젝트 배포 및 운영"`
- 주의: 키움증권 OpenAPI는 Windows COM 기반 — Linux EC2 배포 시 구조 확인 필요 (실시간 API 호출 방식이면 배포 방식 재검토 필요)

**② Spring Boot 실무 경험 없음**
- 학원 수준(3년 전)만 존재, 실무는 Spring MVC 레거시
- 면접에서 솔직하게 인정하되 아래처럼 대응:
  > "Spring의 핵심 개념(IoC, DI, AOP)은 동일하게 적용해왔고, Boot의 auto-configuration과 내장 서버 구조는 개인 프로젝트로 전환하며 빠르게 익히고 있습니다"
- 복습 필요 항목: application.yml, @SpringBootApplication, Spring Data JPA, @RestController, @ControllerAdvice

### 보완이 필요한 부분

**③ 이력서가 SI 납품 문서처럼 읽힘**
- 현재: 기능 구현 나열 (what)
- 필요: 문제 → 해결 → 결과 구조 (why + how + impact)

**④ 프로젝트 컨텍스트 없음**
- 각 프로젝트의 기간, 팀 규모, 사용 기술 스택이 없음
- 어느 항목이 어느 프로젝트 소속인지 불명확

**⑤ Git 팀 협업 경험 없음**
- 개인 GitHub만 사용
- Autowini는 Bitbucket 팀 협업 환경
- 현재 쓸 수 있는 문구: `"개인 프로젝트 GitHub 운영 (브랜치 관리, 커밋 이력 관리)"`

**⑥ 성과 수치 부족**
- 성능 1.7초 개선 — 개선 전 수치가 없음 (예: "8.2초 → 6.5초" 형태로 보완 필요)
- 나머지 항목은 정성적 설명만 있음

**⑦ VWorld + Kakao API가 잘못 분류됨**
- 현재 개인 프로젝트로 인식될 수 있음
- 실제로는 회사 업무에서 사용한 것 → 업무 이력 항목으로 이동 필요

```
신규 조건 추가 시 애플리케이션 코드 수정 없이 데이터로 대응 가능한 구조 구현"
```

```

변경 후:
"기획 변경 3회 반복 과정에서 기존 이진 플래그(2개) 구조의 분기 복잡도 문제를 발견,
단일 상태값 기반 상태 머신으로 재설계 제안 → PM 채택 후 실 적용
→ 이후 기획 변경에도 상태 추가만으로 대응 가능한 구조 확보"
```

## 7. 면접 대비 핵심 스토리 3개

서비스 회사 면접에서 거의 모든 질문에 이 3개로 대응 가능.

### 스토리 1 — 아키텍처 설계 주도 경험
- **상황**: 기획 변경 3회 반복으로 기존 이진 플래그 구조가 복잡해짐
- **행동**: 단일 상태 머신 구조로 재설계 제안, 설계 문서 작성, PM 설득
- **결과**: PM 채택 후 실 적용, 이후 기획 변경에 코드 수정 최소화
- **JD 대응**: "주도적으로 백엔드 아키텍처를 설계해본 경험"

### 스토리 2 — 성능 문제 해결
- **상황**: 민원 접수 목록 조회 성능 저하 이슈 발생
- **행동**: DB 실행계획 분석 → Full Table Scan 구간 식별 → 복합 인덱스 + WHERE 조건 최적화
- **결과**: 약 1.7초 개선 (개선 전 수치 확인 후 "X초 → Y초"로 보완 필요)
- **JD 대응**: "유저가 겪는 문제점을 찾고 기술로 해결"

### 스토리 3 — 구조 개선 제안
- **상황**: 업로드 오류 시 일부 Insert 후 누락 건 미통보 문제 발견
- **행동**: 전체 Rollback + 명확한 에러 메시지 반환 구조로 개선 제안 및 적용
- **결과**: 데이터 정합성 확보, 운영 중 누락 이슈 제거
- **JD 대응**: "백엔드 아키텍처 설계 및 개선"

## 8. 기타 참고 사항

### Spring Boot 전환 시 복습 필요 항목

```
1. application.yml 설정 방식 (vs applicationContext.xml)
2. @SpringBootApplication, 내장 Tomcat 구조
3. Spring Data JPA 기본 (vs MyBatis)
4. REST API 규칙: @GetMapping/@PostMapping/@PutMapping/@DeleteMapping
5. 전역 예외 처리: @ControllerAdvice + @ExceptionHandler
```

### AWS 배포 최소 구성 (이번 주 목표)

```
EC2 t2.micro (프리티어)
→ Java 설치 + jar 실행
→ RDS MySQL 또는 EC2 내 DB
→ 보안 그룹 8080 포트 오픈
→ IP 접근 가능 상태면 배포 완료로 인정 가능
```

주의: 키움증권 OpenAPI가 Windows COM 기반이라면 Linux EC2 직접 배포 불가.  
→ 데이터를 DB에 사전 저장 후 REST API로 조회하는 구조인지 확인 필요.

### 오토위니 외 병행 지원 추천 회사 유형

| 회사 유형 | 이유 |
|----------|------|
| 핀테크 스타트업 | 키움증권 API 경험 직접 활용 가능 |
| 부동산/물류 플랫폼 | VWorld, Kakao 주소 API 경험 연관 |
| B2B SaaS | 복잡한 워크플로우 구현 경험 강점 |
| 중견 이커머스 | Oracle 복잡 쿼리/성능 튜닝 능력 필요 |

### 현재 강점 요약

- Oracle DB 실무 깊이 (복잡 쿼리, 프로시저, 실행계획 분석, 인덱스 튜닝)
- 복잡한 비즈니스 룰을 코드 구조로 해결하는 설계 사고력
- 문제를 먼저 발견하고 개선을 제안하는 능동적 태도 (PM 채택 사례)
- JSP/JavaScript 실무 경험 (JD 필수 요건 충족)
- 외부 API 연동 경험 (키움증권, VWorld, Kakao)
- AI 툴 활용 (Claude Code — JD 우대사항 해당)
